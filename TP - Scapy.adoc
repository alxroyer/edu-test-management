= Sérialisation / désérialisation de protocoles propriétaires avec Scapy
:doctype: article
:sectnums:
:toc: preamble
:toc-title: Sommaire
:icons: font


Objectifs :
manipuler Scapy pour sérialiser et désérialiser des messages d'un protocole propriétaire,
en s'appuyant sur les concepts de couches, de champs et de manipulation de paquets.


== Protocole d'exemple : libp2p Rendezvous

On prend comme protocole d'exemple pour ce TP le protocole Rendezvous de libp2p.

Ce protocole permet à des pairs de s'enregistrer et de découvrir d'autres pairs
via un point de rencontre (rendezvous point).

Les messages principaux sont :

REGISTER::
    Enregistrement d'un pair sous un namespace,
    avec un TTL (Time To Live) optionnel.
DISCOVER::
    Découverte des pairs enregistrés sous un namespace.
UNREGISTER::
    Désenregistrement d'un pair.

Le protocole utilise un identifiant de protocole : /rendezvous/1.0.0
et un format binaire pour les messages.


== Structure des messages

Un message Rendezvous est généralement structuré comme suit (simplifié) :

* Type de message (1 octet).
* Namespace (longueur variable, préfixé par sa taille).
* TTL (4 octets, optionnel).
* Peer ID (longueur variable, préfixé par sa taille).

Exemple de structure pour un message REGISTER :

[source]
----
[Type:1] [Namespace_len:1] [Namespace:var] [TTL:4] [PeerID_len:1] [PeerID:var]
----


== Implémentation avec Scapy

=== Mise en place de l'environnement

Créer un répertoire de travail.
Dans une console bash :

[source, bash]
----
mkdir tp-scapy
cd tp-scapy
----

Installer Scapy dans un environnement venv.

[source, bash]
----
python -m venv .venv
source .venv/bin/activate
python -m pip install scapy
----


=== Imports

Initialiser un fichier `libp2p_rendezvous.py`.

[source, python]
----
#!/usr/bin/env python

from scapy.all import *
from scapy.layers.inet import IP, UDP
from scapy.packet import Packet, bind_layers
from scapy.fields import ByteField, StrField, IntField, FieldLenField
----


=== Définition des couches Scapy

On définit une classe pour chaque type de message
(ou _packet_ en terminologie Scapy),
en héritant de la classe de base `Packet`.

[source, python]
----
class RendezvousMessage(Packet):
    fields_desc = [
        ByteField("type", default=0),
        FieldLenField("ns_len", fmt="B", length_of="namespace", default=None),
        StrLenField("namespace", length_from=lambda p: p.ns_len, default=b''),
        IntField("ttl", default=2*3600),  # 2h en secondes
        FieldLenField("peerid_len", fmt="B", length_of="peerid", default=None),
        StrLenField("peerid", length_from=lambda p: p.peerid_len, default=b''),
    ]
----

Explications :

* Pour créer une classe de message (comme `RendezvousMessage`),
  il suffit d'hériter de la classe `Packet`.

* La définition des champs se fait au travers de la liste `fields_desc`
  (variable de classe).

* `ByteField` décrit un champ de type _byte_, i.e. 1 octet.

* `IntField` décrit un champ de type _int_,
  i.e. 4 octets en terminologie Scapy (héritée de `struct`),
  format BIG ENDIAN par défaut.

* Les champs `FieldLenField` et `StrLenField` permettent de décrire des couples de champs liés :

** Le champ `FieldLenField` constitue une valeur entière
   décrivant la longueur du champ `StrLenField` associé.

*** Le paramètre `fmt="B"` indique la taille du champ.
    En l'occurrence `B` pour _byte_ en terminologie `struct`.
*** Le paramètre `length_of` décrit le nom du champ dont la longueur est contrôlée.
*** La valeur par défaut `None` permet d'assurer le calcul automatique de la valeur en sérialisation.

** Le champ `StrLenField` constitue une valeur de type buffer
   (`Str` i.e. buffer, héritage de python 2),
   dont la longueur est contrôlée par le champ `FieldLenField` associé.

*** Le paramètre `length_of` donne une fonction (fonction _lambda_ en l'occurrence)
    permettant de calculer la taille des données à lire
    à partir du paquet courant `p`.
*** Utile en désérialisation.


=== Sérialisation et désérialisation

Sérialisation::
    A partir d'un objet de message, utiliser la méthode `.build()`
    pour obtenir le buffer sérialisé.
Désérialisation::
    Utiliser la classe pour parser un buffer reçu.

Exemple :

[source, python]
----
print("Sérialisation et désérialisation")
print("================================")

# Création de message.
p = RendezvousMessage(type=1, namespace="test", peerid="QmPeerID")
print("Message créé :")
p.show()

# Sérialisation.
b: bytes = p.build()
print(f"Buffer sérialisé : {b.hex()!r}")
print("")

# Désérialisation.
p = RendezvousMessage(b)
print("Message désérialisé :")
p.show()
----

Exécuter le fichier `libp2p_rendezvous.py` à partir de la console bash :

[source, bash]
----
python libp2p_rendezvous.py
----

Observations :

* Création de message :

** Les champs auto-calculés apparaissent comme `None` tant qu'il n'y a pas eu de sérialisation.

* Sérialisation :

** Les champs auto-calculés ont fait l'objet d'un calcul,
   et se retrouvent correctement sérialisés dans le buffer
   (pas évident à voir sous cette forme...)

* Désérialisation :

** Tous les champs sont correctement parsés avec leur valeur.


=== Raffinement du champ `RendezvousMessage.type`

Ajouter avant la classe `RendezvousMessage`
la définition d'un enuméré explicitant les valeurs de types de messages.

[source, python]
----
import enum

class MessageType(enum.Enum):
    REGISTER = 0
    REGISTER_RESPONSE = 1
    UNREGISTER = 2
    DISCOVER = 3
    DISCOVER_RESPONSE = 4
----

Puis ajuster la définition du champ `type` comme suit :

[source, python]
----
        ByteEnumField("type", enum=MessageType, default=0),
----


=== Empilements protocolaires

Sans que cela corresponde à la définition du protocole Rendezvous,
admettons pour l'exemple que le protocole Rendezvous puisse être véhiculé sur UDP
avec un port destination de 1234.

[source, python]
----
import random

print("Empilements protocolaires")
print("=========================")

# Création de message.
p = (
    Ether()
    / IP(dst="127.0.0.1")
    / UDP(sport=random.randint(1025, 0xffff))  # Port source aléatoire.
    / RendezvousMessage(type=1, namespace="test", ttl=3600, peerid="QmPeerID")
)
print("Message Ethernet créé :")
p.show()
print("Message UDP :")
p[UDP].show()

# Sérialisation.
b: bytes = p.build()
print(f"Buffer Ethernet sérialisé : {b.hex()!r}")

# Désérialisation.
p = Ether(b)
print(f"Message Ethernet désérialisé :")
p.show()
----

Explications :

* Scapy surcharge l'opérateur `/`
  de sorte à permettre l'empilement des couches protocolaires.

* Pour récupérer un pointeur sur une sous-couche protocolaire donnée,
  Scapy surcharge l'opérateur `[]` avec une classe de couche de protocolaire en argument.

* A noter que, lors de la construction du message,
  Scapy renseigne automatiquement les champs de la couche N-1
  permettant de spécifier la nature de la couche protocolaire de niveau N :

** Ether.type = 0x0800 => IPv4
** IP.proto = 0x11 (17) => UDP

* Lors de la désérialisation du message,
  il suffit de désérialiser le message au niveau de la couche protocolaire la plus basse.
  Scapy reconnaît la couche suivante à désérialiser grâce aux mêmes champs que décrits précédemment.

En l'état, la désérialisation n'arrive pas à analyser la payload UDP
en tant que message `RendezvousMessage`.

Ajouter la ligne suivante après la définition de la classe `RendezvousMessage`.

[source, python]
----
bind_layers(UDP, RendezvousMessage, dport=1234)
----

Relancer le programme.

Explications :

* La fonction `bind_layers()` permet d'associer deux couches protocolaires consécutives avec le(s) critère(s) de correpondance.
  Ici les couches UDP et notre protocole Rendezvous.
* En général, le critère de correspondance est l'association d'un champ _type_ de la couche N-1 avec une valeur spécifique.
  Ici, le port de destination UDP associé à la valeur 1234.
* Cette information est utilisée dans les deux sens :
  en sérialisation et en désérialisation comme décrit précédemment pour les protocoles standards.
